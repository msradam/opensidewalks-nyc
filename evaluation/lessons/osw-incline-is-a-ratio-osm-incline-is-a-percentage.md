OSW stores incline as a signed ratio per directed edge; OSM's `incline` tag is a percentage on one way, and a router reads a bare number as a percentage.

TDEI's osm-osw-reformatter 0.4.2 turns an OSW pair of edges into one OSM way and writes `incline=-0.0039;0.0039`. ORS cannot parse that and reads 0, and would read a clean `0.083` as 0.083 percent. On the Brownsville clip, 200 OSW edges are steeper than 6.5% and ORS would read none of them as steep. The reformatter does keep kerb nodes (2,978 of 2,978) and width. A conversion meant for a router has to write `8.3%`, in the direction of the way. Evidence: evaluation/compare/probes/roundtrip_reformatter.json; the converter is scripts/osw_to_osm.py with tests/test_osw_to_osm.py.
