The terrain service writes "no data" as exactly 0.0 inside a tile, so a pixel of exactly 0.0 is not a height.

2026-10-05, v0.3.6. The NY State ImageServer tiles carry no nodata tag. 42% of their pixels are exactly 0.0 (open water, mostly) and 27,875 pixels lie within 5 mm of zero without being zero, so real ground is never exactly 0.0. Up to v0.3.5 Stage 4 read those pixels as ground at 0 m: 218 nodes at exactly 0.0 and others blended toward 0 on shorelines. `assemble._sample_terrain` now treats 0.0 as no height and interpolates a shoreline node from the pixels that hold data when they carry at least half the weight. A test fixture that uses 0 as a real height (two in `tests/test_validity_fixes.py` did) now reads as water; start fixtures at 10 m. This is a different defect from [[rasterio-sample-outside-bounds-is-zero]], which is about points outside a tile.
